Kapan sebaiknya pakai jalur absolut vs relatif dalam skrip bash otomatis?

Halo teman-teman mentor dan praktisi Linux! Saya sedang menyusun skrip pencadangan otomatis (cron job) sederhana untuk memindahkan file log dari direktori aplikasi ke arsip backup. Saat menguji di terminal dengan jalur relatif (cd ./logs && tar -czf ../backup.tar.gz .), semuanya lancar. Namun ketika dimasukkan ke dalam crontab, skripnya gagal mengeksekusi dengan error bahwa direktori tidak ditemukan.

Apakah praktik terbaik (best practice) industri mewajibkan penggunaan full absolute path untuk semua utilitas dan target folder di skrip otomatisasi produksi? Bagaimana cara menangani modularitas jika direktori induknya berpindah-pindah server?

backup-service.sh 
#!/bin/bash
# Upaya pertama menggunakan relative path:
cd ./app/logs/
tar -czf ../archives/log-$(date +%F).tar.gz *

# Error di /var/log/syslog saat dieksekusi via cron:
# /bin/sh: line 1: cd: ./app/logs/: No such file or directory
#bash #path-absolut #automation #cron-job

Pertanyaan yang sangat krusial, Rian! Masalah utama kegagalan skrip kamu di cron adalah karena daemon cron selalu menjalankan perintah dengan direktori kerja bawaan (current working directory) di /home/username atau bahkan /root, bukan di folder tempat skrip .sh berada.

lightbulb Prinsip Emas Otomasi Linux:
  • Cron & Systemd: Selalu gunakan Path Absolut untuk menghindari ambiguitas shell runtime.
  • Modularitas Skrip: Jika ingin tetap dinamis namun aman dari direktori manapun skrip dipanggil, gunakan trik penentu direktori skrip mandiri dengan $(dirname "$0").

Berikut adalah contoh pola penulisan bash script yang standar dan aman untuk produksi:

solusi-terbaik.sh Bash v4.4+ 
#!/usr/bin/env bash
set -euo pipefail

# 1. Tentukan absolute root directory skrip secara dinamis:
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
LOG_DIR="${SCRIPT_DIR}/app/logs"
BACKUP_DIR="/var/backups/myapp"

# 2. Pastikan direktori tujuan tersedia secara absolut
mkdir -p "${BACKUP_DIR}"

# 3. Eksekusi backup dengan path yang sudah dipastikan
tar -czf "${BACKUP_DIR}/log-$(date +%F).tar.gz" -C "${LOG_DIR}" .

echo "[OK] Backup berhasil disimpan ke: ${BACKUP_DIR}"

Menambahkan jawaban dari Mas Budi, ada satu jebakan lain untuk pemula: simbol tilde (~). Tilde sering dikira bagian dari absolute path statis, padahal tilde di-expand oleh shell user aktif. Kalau cron berjalan sebagai user root, ~/data akan mengarah ke /root/data bukannya /home/rian/data. Jadi selalu ketik /home/rian/... secara eksplisit ya!
